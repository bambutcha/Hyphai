## Requirements
### Requirement: Сайдбар диалогов
UI SHALL показывать список диалогов с возможностью создать и выбрать.

#### Scenario: Сайдбар с диалогами
- **WHEN** пользователь открывает приложение
- **THEN** в сайдбаре список заголовков диалогов из API

#### Scenario: Новый чат
- **WHEN** пользователь жмёт «Новый чат»
- **THEN** через API создаётся диалог и становится активным

### Requirement: Область сообщений
UI SHALL показывать сообщения и поле ввода **только** когда выбран активный диалог. В остальных случаях — empty states (см. `chat-empty-states`).

#### Scenario: Просмотр сообщений
- **WHEN** пользователь выбирает диалог
- **THEN** история отображается: user справа, assistant слева

#### Scenario: Отправка
- **WHEN** пользователь вводит текст и жмёт Enter или «Отправить»
- **THEN** сообщение уходит в API, UI обновляется (user + ответ assistant)

#### Scenario: Без выбранного диалога
- **WHEN** активный диалог не выбран
- **THEN** MessagePane с composer не отображается

### Requirement: Визуальный стиль
UI SHALL использовать тёмную тему с акцентами hyphae/грибницы: градиенты, мягкие тени, улучшенная типографика и визуальная иерархия. Все интерактивные элементы SHALL иметь явные affordances: `cursor: pointer` при hover, усиленный hover-state, `focus-visible` при keyboard navigation.

#### Scenario: Тёмная тема по умолчанию
- **WHEN** пользователь загружает приложение
- **THEN** тёмный фон с emerald-акцентами, декоративный фоновый градиент в области чата

#### Scenario: Карточки диалогов
- **WHEN** пользователь видит список диалогов
- **THEN** элементы списка выглядят как интерактивные карточки с hover-состоянием и курсором pointer при наведении

### Requirement: Адаптивность
UI SHALL работать на desktop и mobile: off-canvas drawer для сайдбара на `<768px`, **полностью usable** область сообщений (шапка, лента, composer) без переполнения и с учётом safe-area.

#### Scenario: Мобильный drawer
- **WHEN** ширина экрана < 768px
- **THEN** сайдбар в drawer; чат на полную ширину; поле ввода и кнопка отправки не ломаются и не обрезаются

#### Scenario: Desktop
- **WHEN** ширина экрана >= 768px
- **THEN** сайдбар закреплён слева; layout шапки чата без регрессии

#### Scenario: Шапка чата на mobile
- **WHEN** viewport < 768px и открыт активный диалог
- **THEN** заголовок диалога читаем (truncate); селектор модели и вторичные действия (share, badge) помещаются без горизонтального overflow (перенос на вторую строку или stack)

#### Scenario: Composer на mobile
- **WHEN** пользователь фокусирует поле ввода на mobile
- **THEN** composer остаётся видимым над safe-area; кнопка «Отправить» сохраняет минимальную зону нажатия ≥44px

#### Scenario: Пузыри сообщений
- **WHEN** длинное слово или URL в сообщении на узком экране
- **THEN** текст переносится (`overflow-wrap`); пузырь не расширяет страницу шире viewport

### Requirement: Загрузка данных
UI SHALL показывать индикатор загрузки при первичной загрузке диалогов и истории сообщений.

#### Scenario: Загрузка списка диалогов
- **WHEN** пользователь вошёл и список диалогов ещё не получен
- **THEN** в сайдбаре отображается индикатор загрузки вместо пустого списка

#### Scenario: Загрузка сообщений
- **WHEN** пользователь выбирает диалог
- **THEN** в области сообщений показывается индикатор загрузки до получения истории

### Requirement: Понятные ошибки
UI SHALL показывать человекочитаемые сообщения об ошибках на **русском языке** вместо сырого JSON, технического текста API или английских строк по умолчанию.

#### Scenario: Ошибка сети
- **WHEN** API недоступен (network error)
- **THEN** пользователь видит сообщение о недоступности сервера на русском с возможностью повторить

#### Scenario: Ошибка авторизации
- **WHEN** API возвращает 401 на защищённый запрос
- **THEN** пользователь видит сообщение об истёкшей сессии на русском и перенаправляется на экран входа

#### Scenario: Ошибка валидации
- **WHEN** API возвращает 400/422 с полем `error`
- **THEN** UI показывает локализованный текст ошибки на русском, а не английский оригинал из API

#### Scenario: Ошибка валидации 2
- **WHEN** Когда пользователь вводит некорректный по шаблонам email или пароль и переходит к следующему полю без нажатия кнопки enter
- **THEN** UI предупреждает пользователя локализованным текстом, что введенные данные некорректны и как должно быть правильно

### Requirement: Повтор при ошибке
UI SHALL предоставлять действие «Повторить» для восстановления после сбоя загрузки или отправки.

#### Scenario: Повтор загрузки диалогов
- **WHEN** загрузка списка диалогов завершилась ошибкой
- **THEN** пользователь может нажать «Повторить» и список загрузится снова

#### Scenario: Повтор отправки
- **WHEN** отправка сообщения завершилась ошибкой
- **THEN** текст остаётся в поле ввода и пользователь может отправить снова

### Requirement: Статус realtime-соединения
UI SHALL информировать пользователя о разрыве WebSocket-соединения с активным диалогом.

#### Scenario: WebSocket отключён
- **WHEN** соединение WebSocket закрывается во время активного диалога
- **THEN** в заголовке области сообщений отображается индикатор «Отключено»

#### Scenario: WebSocket подключён
- **WHEN** WebSocket успешно установлен
- **THEN** индикатор показывает «Подключено» или скрывается

### Requirement: Закрываемый баннер ошибок
UI SHALL показывать ошибки чата в dismissible-баннере, который можно закрыть вручную.

#### Scenario: Закрытие баннера
- **WHEN** отображается баннер ошибки в основном интерфейсе чата
- **THEN** пользователь может закрыть его кнопкой dismiss без перезагрузки страницы

### Requirement: Русский интерфейс чата
UI SHALL отображать все пользовательские строки основного интерфейса чата на русском языке.

#### Scenario: Сайдбар на русском
- **WHEN** пользователь вошёл в приложение
- **THEN** кнопка создания диалога, пустое состояние и подзаголовок отображаются на русском

#### Scenario: Область сообщений на русском
- **WHEN** пользователь видит панель сообщений
- **THEN** заголовок, placeholder поля ввода и кнопка отправки — на русском

#### Scenario: Meta и доступность
- **WHEN** пользователь открывает приложение
- **THEN** title страницы и aria-label для удаления диалога — на русском

### Requirement: Анимации интерфейса
UI SHALL использовать мощные, но сдержанные анимации на базе `motion`: layout transitions, spring, stagger, AnimatePresence — для сообщений, переключения чатов и empty states.

#### Scenario: Переход empty → chat
- **WHEN** пользователь выбирает или создаёт диалог
- **THEN** empty state плавно сменяется панелью чата (cross-fade + slide)

#### Scenario: Active chat indicator
- **WHEN** пользователь выбирает другой диалог
- **THEN** индикатор активного элемента плавно перемещается (`layoutId`)

#### Scenario: Появление сообщения
- **WHEN** новое сообщение добавляется в ленту
- **THEN** bubble появляется со spring-анимацией

#### Scenario: Stagger диалогов
- **WHEN** список диалогов загружается
- **THEN** элементы появляются каскадом (stagger)

#### Scenario: Отправка сообщения
- **WHEN** пользователь нажимает «Отправить»
- **THEN** кнопка даёт tactile feedback (scale/spring), опционально краткий glow-pulse

#### Scenario: Reduced motion
- **WHEN** `prefers-reduced-motion: reduce`
- **THEN** анимации отключены или сведены к opacity-only без движения

### Requirement: Переименование диалога в UI
UI SHALL позволять переименовать диалог из сайдбара без отдельной страницы настроек.

#### Scenario: Редактирование названия
- **WHEN** пользователь инициирует переименование (double-click или иконка)
- **THEN** заголовок диалога редактируется inline, сохранение по Enter или blur

#### Scenario: Успешное сохранение
- **WHEN** пользователь вводит валидное название и подтверждает
- **THEN** название обновляется в сайдбаре и заголовке MessagePane

#### Scenario: Отмена
- **WHEN** пользователь нажимает Escape при редактировании
- **THEN** изменения отменяются, отображается прежнее название

### Requirement: Ошибки LLM в UI
UI SHALL показывать локализованные сообщения при сбоях генерации ответа (LLM не настроен, недоступен, rate limit, таймаут).

#### Scenario: LLM не настроен
- **WHEN** API возвращает ошибку о ненастроенном LLM (503)
- **THEN** пользователь видит понятный текст на русском в баннере с возможностью повторить отправку

#### Scenario: Таймаут LLM
- **WHEN** API возвращает ошибку таймаута LLM (504)
- **THEN** текст сообщения остаётся в composer; баннер предлагает повторить

#### Scenario: Ожидание генерации
- **WHEN** пользователь отправил сообщение и API обрабатывает LLM
- **THEN** UI показывает состояние отправки (sending) до получения ответа или ошибки

### Requirement: Маршрутизация landing vs app
UI SHALL показывать landing для гостей и ChatApp для авторизованных на `/`.

#### Scenario: Гость
- **WHEN** нет JWT
- **THEN** landing page (см. `landing-page`)

#### Scenario: Авторизован
- **WHEN** есть JWT
- **THEN** ChatApp

### Requirement: Streaming UI
UI SHALL использовать stream endpoint по умолчанию для отправки сообщений (см. `streaming-chat`).

#### Scenario: Отправка
- **WHEN** пользователь отправляет сообщение
- **THEN** UI подключается к SSE и обновляет ленту по чанкам

### Requirement: Копирование текста сообщения
UI SHALL предоставлять действие копирования plain-text содержимого сообщения в системный буфер обмена без ручного выделения текста.

#### Scenario: Копирование assistant
- **WHEN** пользователь нажимает «Копировать» на пузыре assistant
- **THEN** в буфер попадает `message.content`; показывается toast success на русском

#### Scenario: Копирование user
- **WHEN** пользователь нажимает «Копировать» на пузыре user
- **THEN** в буфер попадает текст сообщения пользователя

#### Scenario: Ошибка clipboard
- **WHEN** `navigator.clipboard` недоступен или запись отклонена
- **THEN** показывается toast error на русском; приложение не падает

#### Scenario: Доступность
- **WHEN** кнопка копирования отображается
- **THEN** у неё есть aria-label на русском; фокусируема с клавиатуры
