## Why

Кнопка «Ветка» должна создавать диалог **только с историей до выбранного сообщения включительно**, но сейчас пользователи получают копию всего чата. Вероятная причина — фильтрация по `created_at <= anchor`, при одинаковых метках времени (пара user+assistant) в ветку попадают все сообщения. Параллельно нет быстрого способа скопировать текст ответа — приходится выделять вручную, что ломает UX на мобильных.

## What Changes

- **Исправление fork**: граница ветки определяется **позицией сообщения в упорядоченной ленте** (`created_at`, затем `id`), а не только timestamp.
- **Копирование сообщения**: кнопка «Копировать» на hover/focus у каждого пузыря (user и assistant); plain-text в буфер + toast success/error.
- **Тесты/проверка**: сценарий «3 пары сообщений → ветка с 2-го → в новом чате ровно 2 сообщения».

### Modified Capabilities

- `hyphae-network`: явное требование — fork копирует сообщения с индекса 0 по выбранное включительно; сообщения после anchor не попадают в ветку.
- `chat-ui`: кнопка копирования текста сообщения в clipboard с обратной связью.

## Impact

- `apps/api/src/routes/conversations.ts` — логика `POST /:id/fork`
- `apps/web/components/MessagePane.tsx` — UI копирования
- `apps/web/lib/ui-text.ts` — строки toast/aria
- Опционально: интеграционный тест API fork (если есть harness)

## Non-goals

- Редактирование/удаление отдельных сообщений
- Fork из share read-only страницы
- Копирование с форматированием markdown/HTML — только plain text `message.content`
- Визуализация дерева веток в сайдбаре
